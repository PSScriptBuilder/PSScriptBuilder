## The problem

You have a PowerShell project split across multiple files. Maybe it's a handful of utility functions, maybe it's a set of classes and enums. It works fine during development — but when it's time to deploy, you're copying folders, making sure files are in the right place, and hoping nothing gets left behind.

There's a better way.

**PSScriptBuilder** collects your source files, resolves dependencies, and merges everything into a single deployable file — automatically, reproducibly, every time.

In this first part of the series, we'll start with the simplest possible case: three standalone functions, three separate files, one output script.

---

## The project

Our example is a small HR utility library. Three functions, each in its own file:

```
01-functions-only/
├── src/
│   ├── Get-FormattedName.ps1
│   ├── Get-YearsOfService.ps1
│   └── Format-Salary.ps1
└── build/
    └── Templates/
        └── HRUtils.ps1.template
```

Nothing unusual — this is how most PowerShell projects start.

## The source files

**`Get-FormattedName.ps1`**

```powershell
Function Get-FormattedName {
    [CmdletBinding()]
    [OutputType([string])]
    param(
        [Parameter(Mandatory = $true)]
        [string] $FirstName,

        [Parameter(Mandatory = $true)]
        [string] $LastName
    )

    return "$FirstName $LastName"
}
```

**`Get-YearsOfService.ps1`**

```powershell
Function Get-YearsOfService {
    [CmdletBinding()]
    [OutputType([string])]
    param(
        [Parameter(Mandatory = $true)]
        [DateTime] $HireDate
    )

    $years = [Math]::Floor(([DateTime]::Today - $HireDate).TotalDays / 365.25)

    if ($years -eq 1) {
        return "1 year"
    }

    return "$years years"
}
```

**`Format-Salary.ps1`**

```powershell
Function Format-Salary {
    [CmdletBinding()]
    [OutputType([string])]
    param(
        [Parameter(Mandatory = $true)]
        [decimal] $Amount
    )

    return $Amount.ToString('C', [System.Globalization.CultureInfo]::GetCultureInfo('en-US'))
}
```

Three files. Three functions. Independent, no dependencies between them.

## The template

PSScriptBuilder uses a **template** as the skeleton of the output file. Placeholders like `{{FUNCTION_DEFINITIONS}}` tell PSScriptBuilder where to insert the source code from your files — the build fills them in automatically.

**`HRUtils.ps1.template`**

```powershell
# HR Utilities
# Generated by PSScriptBuilder - do not edit manually

{{FUNCTION_DEFINITIONS}}
```

That's it. The template defines the structure; PSScriptBuilder fills in the content.
The `# Generated by PSScriptBuilder` comment will appear in the output file — a reminder
not to edit the built result directly. Your source files are the single source of truth.

---

## The build

First, install PSScriptBuilder from the PowerShell Gallery:

```powershell
Install-Module -Name PSScriptBuilder
```

Then the build script:

```powershell
using module PSScriptBuilder

Set-PSScriptBuilderProjectRoot -Path $PSScriptRoot

$templatePath = Join-Path $PSScriptRoot "build\Templates\HRUtils.ps1.template"
$outputPath   = Join-Path $PSScriptRoot "build\Output\HRUtils.ps1"
$srcPath      = Join-Path $PSScriptRoot "src"

$contentCollector = New-PSScriptBuilderContentCollector |
    Add-PSScriptBuilderCollector -Type Function -IncludePath $srcPath

$buildParams = @{
    ContentCollector = $contentCollector
    TemplatePath     = $templatePath
    OutputPath       = $outputPath
}

$result = Invoke-PSScriptBuilderBuild @buildParams

Format-PSScriptBuilderBuildResult -BuildResult $result
```

> **Splatting**: `@buildParams` is a PowerShell idiom for passing a hashtable of named parameters to a cmdlet. It keeps long cmdlet calls readable without relying on backtick line continuations.

Step by step:

1. **`Set-PSScriptBuilderProjectRoot`** — tells PSScriptBuilder where the project root is, so all relative paths are resolved correctly

2. **`New-PSScriptBuilderContentCollector`** — creates the container that holds all collector configurations

3. **`Add-PSScriptBuilderCollector -Type Function`** — registers a function collector that scans `src/` for PowerShell function definitions using AST parsing

4. **`Invoke-PSScriptBuilderBuild`** — runs the build: collects functions, replaces `{{FUNCTION_DEFINITIONS}}` in the template, writes the output file

5. **`Format-PSScriptBuilderBuildResult`** — prints a formatted build summary

## The result

After running the build, `build\Output\HRUtils.ps1` contains:

```powershell
# HR Utilities
# Generated by PSScriptBuilder - do not edit manually

Function Format-Salary {
    ...
}

Function Get-FormattedName {
    ...
}

Function Get-YearsOfService {
    ...
}
```

One file. Ready to deploy. The build summary confirms what was collected:

```

  Output : build\Output\HRUtils.ps1
  Size   : 0.54 KB
  Time   : 12 ms

Components
  Functions : 3
  Total     : 3
```
